# 农场助手 1.21.0

## 更新与启动

1. 首次安装：将 Git 仓库保存在固定位置，在 Chrome / Brave 扩展管理页开启开发者模式，选择“加载已解压的扩展程序”，选择本仓库的 extension 文件夹。
2. 更新：双击仓库根目录的“更新助手.command”（Mac），或在仓库目录执行 `git pull --ff-only origin main`。然后到扩展管理页点击本扩展的“重新加载”。
3. 等当前战斗结束、农务队列完成后刷新游戏，确认面板版本。先完成游戏版本检查；未归类代码变化时自动功能暂停，核对兼容后由你确认；已核实的缓存/文案变化自动放行。
4. 勾选需要的农务；战斗由你手动开局，再开启唯一的「自动战斗」开关。不会自动重复开局。

刷新后农务恢复原账号设置，战斗需手动开启。Esc停止自动操作；页面隐藏、人工操作或出现验证时按现有规则暂停。战斗页面仍可见时，切到其他窗口不会因失焦暂停；升级选择和目标金币撤退同样适用。最小化或切换标签页后游戏可能自行暂停，需按游戏提示继续。验证由用户处理。面板标题可拖动，「收起」可缩小显示。

## 战斗结束自动回村庄

助手观察到本局正式战斗后，结算界面收到服务器返回的排名/杯赛结果，且页面连续5秒无手动操作时，自动点击游戏“回村庄”按钮。页面内鼠标移动、点击、滚动、键盘或输入会重置计时；按住按键或鼠标时不返回，Esc 取消本局自动返回。切换页面、验证、版本检查或弹窗会等待，恢复后重新计时。不自动开下一局，不改变原农务开关。未收到结算确认时保留在结算页，需检查网络或手动处理。只能观察游戏页面内操作，不能感知其他窗口里的鼠标和键盘操作。

## 收获优先与补粮

田地所选非粮食作物在今日收获尚有实际余额时继续种植；不再用预计成熟产出或待支付结转当成已经满额，作坊/次日备货缺小麦也不提前自动改种。实际满额后再补玉米/小麦；未启用市场补料时仍会补作坊小麦并保留饲料。“按今日额度安排种植”开启时，粮食达到储备天数则暂停。用户主动选择小麦/玉米可在未满额时种粮。既有库存加工和动物喂养照常进行；库存缺粮的订单加工可能等收获满额后再补粮。日志记录播种原因与提交时已得/上限，不回改过去的历史记录。

## 新版再投资与奖励补足

游戏新前端开启了适用农场建设/市政厅升级的 20% 再投资折扣、奖励补足额度、恢复模式及全服奖励池目标。消费进入游戏通用消费函数时，按消费金币乘消费计价价格的 60% 累计美元补足额度；奖励发放比例低于 100% 时，部分收获、结转支付、村庄和战斗奖励会在额度允许范围内补足。实际支付、支持范围及全服目标加成仍以服务器为准，不能由前端静态代码证明玩家市场等所有服务端交易都获得额度。

内部读取服务器的 fullRate 与 today.fullRateBonus，收益界面不重复游戏已有的补足额度。不预支未来信用、不把补足重复加到 harvestEarned / battleEarned / 订单额度。订单支付路径未看到相应补足调用，自动采购继续按原金币奖励与实际成本保守判断，不把消费新产生的信用当作订单利润或额外购买依据。游戏商店的建设折扣不会一概套到能量、饲料或市场价格。

恢复模式开启且发放比例低于 50% 时，新前端的普通消费计算将销毁比例设为 0；能量仍走全部进入奖励池的原路径。这描述的是前端消费规则，不代表已经逐笔审计所有链上结算。全服目标数据与额外24小时加成不由助手自行猜测或叠加。

移动、放置等农场编辑模式中暂停自动农务，避免游戏拒绝操作后留下未完成任务。用户在游戏点“完成”回到 normal 模式后继续原设置；不自动替用户结束编辑或刷新游戏。暂停期间已有待确认任务保留，计时不累计。

## 作坊订单与自动盈利采购

作坊总开关为“自动作坊与订单”，下面分别控制：

- **完成仅奖励星星的订单**：开启后允许用库存、自产材料完成；关闭后不为已确认的纯星星订单备料或交付。为保持此前行为，首次升级默认允许完成，可随时关闭。
- **自动采购有利润的订单**：不用填写单价上限和每日预算。新安装默认关闭，升级保留此前的采购开关。旧版手动限价、预算不再作为采购条件。

金币订单先抵扣现有成品及可按时完成的队列，再比较直接买成品、买中间材料加工、买原料加工的成本；共享材料不重复分配，动物饲料的小麦继续保留。加工能量按游戏商店 10 点小包的单价折算，不卖出库存，也不按市场卖价给已有库存估值。

**本订单已采购成本 + 待采购成本 + 已投入及新增加工能量折算 ≤ 当前预计可领金币 × 90%** 才允许采购。预计可领金额取当前订单显示值、按当前价格/比例计算的奖励、账号剩余额度、全服预算的保守值；已显示的实际奖励不会再乘一次折扣。不是拿原始标价或明日预测奖励作为依据。每次点购买前强制刷新全服预算和市场报价，条件变化即停购。现金支出还必须在现有余额内。

一次只跟进一张已经投入采购或加工成本的订单，减少库存与额度被其他订单重复使用。每次通过游戏原始“买 1”按钮采购，确认库存增加且金币扣除后再重算；未知结果不重复购买。超过 3 分钟未确认后，请先在游戏核对，再使用“我已核对未成交，停止等待”，该操作关闭自动采购并保留已记成本，避免模糊结果导致重复花费。

展开“订单采购评估”，查看预计可领金币、已经采购、还需采购、加工能量折算及预计净增；不采购时显示原因。总成本是当前库存口径下的增量成本，不代表把原材料市场卖价也算进去的经济利润。全服预算可能被别人抢先用完，市场供应及价格也会变化，10% 余量不能保证最终不亏。

成本按账号及 UTC 订单日保存，刷新和本地午夜不清空同一张订单已经投入的成本；北京时间 08:00 订单刷新后开始新订单日。面板“今日助手采购”仍按农场本地日统计，仅供查看，不是预算。手动采购、其他浏览器/电脑的支出不在本助手的订单成本里。旧版已有未归属订单的采购金额保守计入本订单日，不当作免费材料。

纯星星订单不采购。次日预测的奖励未知，也绝不提前采购；开启备货时只用现有/自产材料。当前已经投入的加工队列不撤销，刷新后按实际奖励及纯星星开关重新安排。

## 多农夫与施工

读取游戏实际农夫池，分别确认每人的施工、农务忙碌、钓鱼和排队状态。有空闲农夫时允许提交不冲突的农活，不因其他农夫施工或其挂起队列而全局停工。原有田地种收、动物收喂、材料与能量相关任务仍检查队列冲突；所有人忙碌、状态无法确认或旧任务待确认时等待。不会重新分配、清空已有队列，也不绕过游戏原有调度。执行详情显示人数和排队数量。

## 奖励池发放比例

从当前账号农场快照读取 `price.mult`，按游戏前端相同的有效比例边界与取整顺序计算。收益页不再重复显示比例，收获基础上限、结转容量、村庄收入、战斗和订单基础额度、作物/动物/果园估值纳入比例。NFT/银行加成继续独立计算，已花饲料返还额度与消费价格不额外乘比例。已得金币、余额、已存结转和服务器显示的订单奖励不再次打折；订单材料数量不变，纯星星任务按独立开关处理。比例缺失时内部按100%估算，但不允许据此自动购买能量；明确无效时等待有效数据。沿用30秒农场数据刷新，不自行推算奖励池，也不伪造每10分钟的比例更新。

## 分级兼容性检查

- **已核实缓存变化**：仅已确认的资源URL包装器缓存参数及其入口引用文件名变化，逐文件内容核对后自动忽略。不忽略任意文件名或任意 `?v=` 参数。
- **已审核文案变化**：只限 `src/update-catalog.js` 中保存的完整文件 SHA-256 与审核分组，且所有其他关联文件、入口必须匹配。当前只收录已核对的提现说明更新与其关联缓存文件；不会删掉任意字符串后宣称逻辑相同。保留原始批准基准与已审核逻辑摘要。
- **未知代码变化**：包括未归类的功能、价格、奖励、配方、字段、规则和模块增减，仍暂停全部自动功能。当前页面混用旧资源时须先刷新再确认；本助手不会自动刷新或批准。上报字段相同不代表代码或服务端规则相同。
- **运行中接口异常**：只读观察正常 fetch 调用，校验已覆盖字段的存在、类型及少量关键约束。市场异常暂停市场采购，订单异常暂停作坊；农场关键数据异常暂停依赖其数据的农务、战斗、收益读取；身份失效或兼容记录不可用暂停全部自动操作。原开关保留。

覆盖同源 `/api/farm`、`/api/farm/ops`、`/api/farm/order`、`/api/farm/market`、`/api/farm/market/buy`、`/api/farm/battle/start`、`/api/farm/battle/end` 的普通 fetch JSON 调用。请求只检查已支持操作的顶层字段及部分队列/统计结构；响应检查农场关键状态、GET 订单预算、GET 市场列表、战斗开局标识。成功交单的 POST 回执不要求含 GET 预算。业务拒绝与非成功响应不直接当成字段更新，401 单独提示重新登录。不解析认证接口、请求头、Cookie、钱包、签名或验证令牌。

不会修改、阻断或重放游戏请求，不消耗游戏自身响应；观察复制的响应，超过1MB不解析。不是完整协议审计：不覆盖 XHR、WebSocket、sendBeacon、非JSON/流式请求和所有嵌套字段，也不判断更新是否针对脚本。异常操作本身可能已经发出，保护从识别异常后的助手动作生效。

局部暂停提示可展开查看范围与原因。「重新检查相关功能」仅对受影响的农场、订单预算或市场接口作两次 GET；连续两次符合原契约才清除同一响应异常，不学习新字段，不开战或采购。请求格式变化需更新助手或等待后续正常请求确认；不会为测试而重新提交请求。只在本地保存异常类别、范围与通用说明，不保存请求/响应内容或账号数据。

## 简化收益与执行面板

默认只显示收获/战斗是否满额、作坊已完成几张及必要的限制原因与重置时间。具体已得/上限、账号剩余订单额度、与全服预算共同限定的当前可获上限放在一个「额度明细」中；不重复展示游戏HUD中的余额、能量、加成、补足、库存与经济规则。

全服预算为零与账号额度用完分别提示「仅星星」，交完三张则显示完成；不会把全服预算耗尽时的账号剩余额度当作仍可领金币。过期、跨日或兼容性未确认的数据不标成当前完成情况。

标题/标签固定、内容区滚动。操作页保留独立深色执行区，显示当前动作、原因和下一步；材料库存与最近记录折叠在执行详情。收益页默认显示一条执行摘要，可点击展开；异常自动展开。原有位置、收起、标签和功能开关不重置。

## 次日订单备货

在“作坊”页开启“自动作坊与订单”后，“提前备次日订单”默认勾选，可随时关闭并按账号记住选择。展开“次日备货计划”查看次日三张候选订单、材料缺口、队列覆盖与是否晚于刷新完成。

- 先用今天实际订单核对预测规则，匹配后才按当前公开的账号/日期算法预测明天；交单只读当天真实订单，不提交预测结果。
- 今天允许完成的订单优先，空闲作坊再用库存备明天；奶酪、布料等长加工优先准备。
- 保留鸡蛋、牛奶和羊毛的库存缺口，统计队列剩余产出，遵守队列和库存容量。没有建成的工厂不为其额外囤原料。
- 预留今天和明天的订单面包，只吃剩余部分补能。材料成熟后按整类动物收取，可能略超需要量。
- UTC 00:00（北京时间08:00）刷新后先重新读取真实订单，未读取前暂缓动物批量收取。若实际订单与预测规则不一致或开放范围变化，暂停预测备货并显示原因，今天实际订单照常处理。
- 次日奖励未知，不提前为次日采购；也不自动建造或上架出售。能量、饲料及缺料可能延后准备，不能保证刷新即完成；全服金币预算也可能已耗尽。
- 订单预算通常按30秒缓存，由农务和收益页共用，交单后失效；每次实际采购前强制刷新核对。

## 当前功能

- 战斗：自动寻敌、正常闪避/风暴、升级选卡，统一生存优先；没有竞速模式、无敌、回血或冷却修改。小史莱姆优先走位，安全赶路使用闪避；波末在门口下方连续安全范围内每波选择位置，危险时重选。
- 升级：弹窗后随机等待1.1～3.5秒，按现有优先级选择，未知效果优先第一项可用选项。
- 本局目标金币：默认今日战斗上限减本局开始前今日累计，开局确定后固定。可输入非负整数后「应用」，或「恢复默认」。达到后先停止自动战斗，再通过游戏原有撤退流程发起结算，不会再次开局。
- 本局金币按已计入金币加待入账整数部分计算，不提前计入未拾取掉落，不向上凑浮点尾差。实际结算可能因游戏收尾拾取而略高于目标；最终结果由服务器决定。
- 田地：自动收获与补种，作物可选；保留能量、额度安排和满额后玉米/小麦规则按界面设置执行。
- 动物、作坊、日常：保留喂养/收集、订单和加工、钓鱼、村庄/矿油收取等现有选项；涉及金币消费需按面板设置开启并设置预算。
- 织布坊：纳入“自动作坊与订单”；按需求保留、收取羊毛，2份羊毛制作1份布料（2小时）。优先保留直接交单材料，统计库存与排队成品，遵守8批队列、200份库存和订单刷新时间；未建成时提示等待，不自动建造或买材料。
- NFT质押：按服务器返回的生效状态与锁定天数，计算收获额度+25%及7/14/28天对应的5%/10%/15%产出加成；由游戏页面显示加成，助手只用于计算。不额外放大战斗、订单或村庄收入额度。
- 收益：显示今日完成情况及可展开的额度明细；战斗中的今日已得已接入新的本局金币数据。

## 测试记录

打开浏览器工具栏的助手扩展图标 →「测试记录」：

- **开始手动对照记录**：关闭所有自动开关，之后由你手动操作。记录结束后开关保持关闭。
- **开始助手测试记录**：保留原开关，不主动开启功能；由你开启所需功能、手动开始战斗。停止记录只结束采集，不停止助手。
- 等结算与农务服务器响应完成，点「停止记录」→「导出脱敏记录」。手动文件以前缀 farming-manual-baseline 命名，助手文件以前缀 farming-assistant-test 命名。

只观察当前标签页同源 POST /api/farm/ops、/api/farm/battle/start、/api/farm/battle/end。不拦截或修改请求，不记录请求头、Cookie、登录/钱包接口、签名或验证令牌；会话ID本地标签化，响应仅保留允许的字段。不是完整HAR或服务器规则审计。

记录期间顶部调试提示持续显示。30分钟、300条、页面导航或连接断开会结束采集。记录保存在扩展会话存储，关闭浏览器后可能丢失，请及时导出。开始新记录会替换扩展内上一份记录，不改变已导出的文件。手动记录意外断开后若需恢复助手，请刷新游戏。
