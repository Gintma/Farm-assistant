# 农场助手 1.20.5

## 更新与启动

1. 首次安装：将 Git 仓库保存在固定位置，在 Chrome / Brave 扩展管理页开启开发者模式，选择“加载已解压的扩展程序”，选择本仓库的 extension 文件夹。
2. 更新：双击仓库根目录的“更新助手.command”（Mac），或在仓库目录执行 `git pull --ff-only origin main`。然后到扩展管理页点击本扩展的“重新加载”。
3. 等当前战斗结束、农务队列完成后刷新游戏，确认面板版本。先完成游戏版本检查；检测到变化时自动功能暂停，核对兼容后由你确认。
4. 勾选需要的农务；战斗由你手动开局，再开启唯一的「自动战斗」开关。不会自动重复开局。

刷新后农务恢复原账号设置，战斗需手动开启。Esc停止自动操作；页面隐藏、人工操作或出现验证时按现有规则暂停。战斗页面仍可见时，切到其他窗口不会因失焦暂停；升级选择和目标金币撤退同样适用。最小化或切换标签页后游戏可能自行暂停，需按游戏提示继续。验证由用户处理。面板标题可拖动，「收起」可缩小显示。

## 战斗结束自动回村庄

助手观察到本局正式战斗后，结算界面收到服务器返回的排名/杯赛结果，且页面连续5秒无手动操作时，自动点击游戏“回村庄”按钮。页面内鼠标移动、点击、滚动、键盘或输入会重置计时；按住按键或鼠标时不返回，Esc 取消本局自动返回。切换页面、验证、版本检查或弹窗会等待，恢复后重新计时。不自动开下一局，不改变原农务开关。未收到结算确认时保留在结算页，需检查网络或手动处理。只能观察游戏页面内操作，不能感知其他窗口里的鼠标和键盘操作。

## 收获优先与补粮

田地所选非粮食作物在今日收获尚有实际余额时继续种植；不再用预计成熟产出或待支付结转当成已经满额，作坊/次日备货缺小麦也不提前自动改种。实际满额后再补玉米/小麦；未启用市场补料时仍会补作坊小麦并保留饲料。“按今日额度安排种植”开启时，粮食达到储备天数则暂停。用户主动选择小麦/玉米可在未满额时种粮。既有库存加工和动物喂养照常进行；库存缺粮的订单加工可能等收获满额后再补粮。日志记录播种原因与提交时已得/上限，不回改过去的历史记录。

## 作坊市场补料

在“作坊 → 市场补料设置”中，填写每日采购预算；通过物品下拉框分别设置面包、面粉、鸡蛋、小麦、牛奶、黄油、奶酪、羊毛、布料的每份最高价，最后勾选“允许市场补料”。新版本默认关闭，所有限额初始为 0；0 代表不买对应物品。单位均为游戏金币（SEASON），不是能量或美元。原有作坊总开关也需要开启。

先抵扣现有成品和可按时完成的队列，剩余订单比较买成品、买中间材料加工、买原料加工。共享的牛奶、鸡蛋、面粉等不能重复使用；保留粮仓的动物饲料。加工能量按商店 10 点小包的单价折算，连同采购金币比较；不卖出库存，也不按市场卖价给现有库存估值。不跨越队列容量或订单刷新时间。先满足今天，再为已核对预测规则的次日订单准备；不为自动吃面包补能单独采购。限额、缺货或报价读取失败时等待，已有材料可继续加工。

这是当前可见报价和现有配方下的最低估算方案，无法预测未来行情、尚未产出的材料或成交竞争。不保证每笔都能成交。通过游戏原始“买 1”按钮逐份购买，每次等待服务器库存增加并扣币后重算；单价、余额、总预算或页面报价不符即停止。预算在提交前保留，刷新后继续占用；结果不明不会重复购买。超过 3 分钟未确认后，可先在游戏里核对，再使用“我已核对未成交，停止等待”，该操作会关闭市场补料并保留预算占用。

每日预算按账号的本地日历日重置，只统计当前浏览器助手的采购；手动购买、其他浏览器或其他电脑的支出不在此额度中。预算不包含能量的折算成本或其他自动功能支出。更新不会替你开启此功能或填写可花费额度。

## 多农夫与施工

读取游戏实际农夫池，分别确认每人的施工、农务忙碌、钓鱼和排队状态。有空闲农夫时允许提交不冲突的农活，不因其他农夫施工或其挂起队列而全局停工。原有田地种收、动物收喂、材料与能量相关任务仍检查队列冲突；所有人忙碌、状态无法确认或旧任务待确认时等待。不会重新分配、清空已有队列，也不绕过游戏原有调度。执行详情显示人数和排队数量。

## 奖励池发放比例

从当前账号农场快照读取 `price.mult`，按游戏前端相同的有效比例边界与取整顺序计算。收益页显示比例，收获基础上限、结转容量、村庄收入、战斗和订单基础额度、作物/动物/果园估值纳入比例。NFT/银行加成继续独立计算，已花饲料返还额度与消费价格不额外乘比例。已得金币、余额、已存结转和服务器显示的订单奖励不再次打折；订单材料及星星任务照常处理。比例缺失时标注按100%估算，但不允许据此自动购买能量；明确无效时等待有效数据。沿用30秒农场数据刷新，不自行推算奖励池，也不伪造每10分钟的比例更新。

## 缓存更新过滤

已确认的资源URL包装器仅缓存参数变化、并仅引起对应入口/资源引用文件名变化时，逐文件内容核对后自动忽略，标题显示“缓存更新已忽略”。实际逻辑、功能开关、规则或模块增减仍暂停。不会忽略所有文件名或任意?v=参数。首次升级如旧基准与当前文件不同，仍需刷新、核对并确认一次，之后使用新的内容摘要；既有待确认更新不会被静默解除。

## 次日订单备货

在“作坊”页开启“自动作坊与全部订单”后，“提前备次日订单”默认勾选，可随时关闭并按账号记住选择。展开“次日备货计划”查看次日三张候选订单、材料缺口、队列覆盖与是否晚于刷新完成。

- 先用今天实际订单核对预测规则，匹配后才按当前公开的账号/日期算法预测明天；交单只读当天真实订单，不提交预测结果。
- 今天的材料与加工需求优先，空闲作坊再备明天；奶酪、布料等长加工优先准备。
- 保留鸡蛋、牛奶和羊毛的库存缺口，统计队列剩余产出，遵守队列和库存容量。没有建成的工厂不为其额外囤原料。
- 预留今天和明天的订单面包，只吃剩余部分补能。材料成熟后按整类动物收取，可能略超需要量。
- UTC 00:00（北京时间08:00）刷新后先重新读取真实订单，未读取前暂缓动物批量收取。若实际订单与预测规则不一致或开放范围变化，暂停预测备货并显示原因，今天实际订单照常处理。
- 不自动建造、购买市场原料或上架出售。能量、饲料及缺料可能延后准备，不能保证刷新即完成；全服金币预算也可能已耗尽。
- 预算按30秒缓存，由农务和收益页共用，交单后失效重读。

## 当前功能

- 战斗：自动寻敌、正常闪避/风暴、升级选卡，统一生存优先；没有竞速模式、无敌、回血或冷却修改。小史莱姆优先走位，安全赶路使用闪避；波末在门口下方连续安全范围内每波选择位置，危险时重选。
- 升级：弹窗后随机等待1.1～3.5秒，按现有优先级选择，未知效果优先第一项可用选项。
- 本局目标金币：默认今日战斗上限减本局开始前今日累计，开局确定后固定。可输入非负整数后「应用」，或「恢复默认」。达到后先停止自动战斗，再通过游戏原有撤退流程发起结算，不会再次开局。
- 本局金币按已计入金币加待入账整数部分计算，不提前计入未拾取掉落，不向上凑浮点尾差。实际结算可能因游戏收尾拾取而略高于目标；最终结果由服务器决定。
- 田地：自动收获与补种，作物可选；保留能量、额度安排和满额后玉米/小麦规则按界面设置执行。
- 动物、作坊、日常：保留喂养/收集、订单和加工、钓鱼、村庄/矿油收取等现有选项；涉及金币消费需按面板设置开启并设置预算。
- 织布坊：纳入“自动作坊与全部订单”；按需求保留、收取羊毛，2份羊毛制作1份布料（2小时）。优先保留直接交单材料，统计库存与排队成品，遵守8批队列、200份库存和订单刷新时间；未建成时提示等待，不自动建造或买材料。
- NFT质押：按服务器返回的生效状态与锁定天数，计算收获额度+25%及7/14/28天对应的5%/10%/15%产出加成；额度明细单独显示。不额外放大战斗、订单或村庄收入额度。
- 收益：显示今日额度、库存与订单等进度；战斗中的今日已得已接入新的本局金币数据。

## 测试记录

打开浏览器工具栏的助手扩展图标 →「测试记录」：

- **开始手动对照记录**：关闭所有自动开关，之后由你手动操作。记录结束后开关保持关闭。
- **开始助手测试记录**：保留原开关，不主动开启功能；由你开启所需功能、手动开始战斗。停止记录只结束采集，不停止助手。
- 等结算与农务服务器响应完成，点「停止记录」→「导出脱敏记录」。手动文件以前缀 farming-manual-baseline 命名，助手文件以前缀 farming-assistant-test 命名。

只观察当前标签页同源 POST /api/farm/ops、/api/farm/battle/start、/api/farm/battle/end。不拦截或修改请求，不记录请求头、Cookie、登录/钱包接口、签名或验证令牌；会话ID本地标签化，响应仅保留允许的字段。不是完整HAR或服务器规则审计。

记录期间顶部调试提示持续显示。30分钟、300条、页面导航或连接断开会结束采集。记录保存在扩展会话存储，关闭浏览器后可能丢失，请及时导出。开始新记录会替换扩展内上一份记录，不改变已导出的文件。手动记录意外断开后若需恢复助手，请刷新游戏。
